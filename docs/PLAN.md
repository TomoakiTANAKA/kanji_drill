# 家庭学習サイト 計画書

子どもと自分だけが使う家庭学習Webサイト。
習い事の算数宿題を「段階的な穴埋め（フェーディング）」で解けるようにする機能を新しく作り、既存の漢字（国語）学習サービスを統合する。

---

## 1. 目的

- 算数：解説を口で聞かせるのではなく、**段階的に空欄が増えていく類題**を子どもが自力で進め、最後に宿題本体を解けるようにする
- 漢字：既存の漢字テスト・学習機能を同じサイトに統合し、入口と記録を一本化する
- 利用者は親子の2人のみ。外部公開はしない

## 2. 前提・方針

- 対象は**習い事の宿題（先取り学習）**。学校の宿題には使わない
- 宿題は1回あたり4ページ程度、1問の粒度は「割合(4)」の (1)(2) くらい
- コンテンツは自動生成しない。**親がClaudeとの会話で作り、目で論理チェックしてから置く**
- 足場は**型ごとに最初の1問だけ**。同じ型の2問目以降はそのまま解かせ、詰まった問題だけ後から足場を出す
- 小数のかけ算は既習

## 3. 技術構成

| 項目 | 採用 | 備考 |
|---|---|---|
| フレームワーク | Next.js（App Router, `output: "export"` で静的出力） | |
| コンテンツ | Markdown（算数）／CSV（漢字・既存流用） | |
| ホスティング | 当面 GitHub Pages（旧漢字サイトと同じ URL）→ Cloudflare Pages | 静的ファイルを配置 |
| 認証 | Cloudflare Access（One-time PIN／メール認証） | 許可リストは親のメールアドレス。サイト全体にかける |
| 学習記録 | localStorage | 既存の漢字サービスと同じ方式。`lib/storage.ts` 経由 |
| 将来のAPI保存 | Cloudflare Pages Functions + D1 | 無料枠で収まる想定。`lib/storage.ts` の `subscribe()` から同期する |

### 認証まわりの運用
- 子どもの端末は最初に親がログインしておく
- Access のセッション時間は長めに設定し、子どもが毎回コード入力しなくて済むようにする
- 無料枠（50ユーザーまで）に収まる想定。条件は導入時にCloudflareの最新情報を確認する

### SSR ではなく静的出力にした理由
- ページの中身は content/ のファイルだけで決まり、ビルド時に HTML にできる（＝SSG。見た目は SSR と同じくサーバで作った HTML）
- 本当の SSR を Cloudflare でやるには OpenNext アダプタ（Workers）が必要で、構成が重くなる
- API が必要になったら、静的サイトのまま `functions/api/*.ts`（Pages Functions）を足せる

## 5. 算数コンテンツの仕様

### 5.1 ファイルの分け方

- 1単元（1つの型）＝1フォルダ
- 段階ごとに1ファイル。番号が大きいほど空欄が多い
  - `01.md`：例題。全ステップが書いてあり、最後の答えだけ空欄
  - `02.md`：数字を変えた類題。後ろ2つが空欄
  - `03.md`：数字を変えた類題。質問だけ残し、答えは全部空欄
  - `04.md`：問題文だけ（宿題本体）
- 段階数は固定しない（3つでも5つでもよい）
- 各段階で**数字を変える**（前の回の答えを写せないようにする）

### 5.2 Markdownの書き方

```md
---
title: 割合(4) 利益を上乗せ ①
unit: wariai-4-rieki
order: 1
source: 基本トレーニング 文章題・図形5級 p.30 大問1(1)
---

200円で仕入れた品物に、20%の利益をみこんで定価をつけました。定価はいくら？

1. 定価は200円より高い？低い？ → 高い
2. もとにする数は？ → 仕入れ値の200円
3. 200円を100%とすると、定価は何%？ → 100%＋20%＝120%
4. 120%は何倍？ → 1.2倍
5. 式と答え → 200 × 1.2 ＝ [[240]]円
```

- **空欄記法**：`[[答え]]`
- mdを直接読めば答えまで分かる状態にしておく（目での論理チェック用）

### 5.3 空欄の表示仕様

- `[[...]]` を `<Blank answer="..." />` に置き換えて表示する
- 初期表示：空の枠
- タップ／クリックで答えを表示（自己採点）
- 数値の入力欄と正誤の自動判定は**後回し**（画面で解くか紙で解くかが決まってから判断）

### 5.4 図（任意）

- 数直線などの図が必要な場合は、mdに埋め込める形（コードブロックのテキスト図、またはSVGファイル参照）で入れる

## 6. 漢字サービスの統合

### 6.1 現状

- JSON（問題データ）＋ HTML/CSS/JS で作られている
- 学習記録は localStorage に保存している

### 6.2 移行方針

1. 既存JSONを `content/kanji/` にそのまま移す（形式は変えない）
2. 画面をReactコンポーネントに移植する。まずは見た目と動きを今と同じにする
3. localStorage は**既存のキー名とデータ形式をそのまま使う**
   - 同じドメインで動かせば、それまでの記録を引き継げる
   - 旧サービスと新サイトのドメインが違う場合、localStorage はドメインごとに分かれるので引き継げない。その場合は旧サービス側に「記録をJSONで書き出す」機能を一時的に追加し、新サイトで読み込む
4. `lib/storage.ts` で算数・漢字の記録の読み書きを共通化する

### 6.3 移行前に確認すること
- [x] 既存の localStorage のキー名一覧とデータ形式 → `kanji_drill_v2` / `kanji_drill_excluded_v1` / `kanji_retest_v1` / `kanji_retest2_v1`。そのまま使う
- [x] 既存サービスが今どのドメインで動いているか → GitHub Pages（このリポジトリ）。同じ URL に新サイトを出せば記録はそのまま
- [x] 既存のデータ形式 → JSON ではなく CSV。形式は変えずに `content/kanji/` へ移した
- Cloudflare に移るときは `/records/` で記録を JSON で書き出し、新しい URL で読み込む

## 7. 学習記録（localStorage）

- 算数：単元ごとに、どの段階まで終わったか・いつやったか
- 漢字：既存の形式を維持
- キーには接頭辞をつけて衝突を防ぐ（例：`math:progress`）。漢字の既存キーは変えない

**制約**：localStorage は端末・ブラウザごとに別なので、複数端末で記録は共有されない。必要になったら Cloudflare D1 / KV と Pages Functions で同期する（今回の範囲外）

## 8. コンテンツ作成の流れ

1. 宿題のページを撮影する
2. Claudeとの会話で、型の判定 → 例題 → 段階的な類題（md）を作る
3. 親がmdを読んで論理・計算をチェックする
4. `content/math/<単元>/` に置いてコミット
5. pushすると Cloudflare Pages が自動でデプロイする
